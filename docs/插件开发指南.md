# 插件开发指南（MCP Plugin）

## 插件是什么

一个插件 = `plugins/<名字>/` 目录 + 一个 `manifest.json`，可选配一个 MCP 服务器脚本和一个 bot 端调度器脚本。

机器人启动时会扫描 `plugins/` 下所有 `*/manifest.json`，按里面的声明自动装配。不改机器人主代码，就能加新能力。

## 一个插件能做什么

插件有三种能力，可以只用其中任意几个，也可以全用：

1. **提供 MCP 工具**（`mcp` 字段）
   自己的 MCP 服务器，注册成 `namespace-工具名`，LLM 可以调用。
   比如 revive 提供 `revive-love_tick`、`revive-love_record_reply`。

2. **后台轮询任务**（`trigger` 字段）
   bot 端一个后台线程，每隔 N 秒调一次你的代码。适合"主动做事"，
   比如定时检查、主动问候。MCP 是别人调你，trigger 是你主动做事。

3. **监听用户回复**（`on_user_reply` 字段）
   用户每次发消息，你的钩子都会被调用。适合做学习/记录类的事。

## 目录结构

```
plugins/
└── myplugin/                  # 目录名就是插件名（namespace）
    ├── manifest.json          # 必填，插件声明
    ├── server.py              # 选填，MCP 服务器（FastMCP + stdio）
    └── trigger.py             # 选填，bot 端调度器/钩子逻辑
```

## manifest.json 长什么样

```json
{
  "name": "myplugin",
  "description": "一句话说明这插件干嘛的",

  "mcp": {
    "command": "runtime/python.exe",
    "args": ["plugins/myplugin/server.py"],
    "expose_to_llm": true
  },

  "trigger": {
    "module": "plugins.myplugin.trigger",
    "class": "MyTrigger",
    "interval": 60
  },

  "on_user_reply": {
    "module": "plugins.myplugin.trigger",
    "function": "on_user_reply"
  }
}
```

字段说明：

| 字段                     | 含义                                                                                                 |
| ------------------------ | ---------------------------------------------------------------------------------------------------- |
| `name`                   | 插件名，同时是工具 namespace。工具全名 = `name-工具名`                                               |
| `mcp.command`            | 运行 MCP 服务器的 python。用 `runtime/python.exe`（便携包）或 `.venv/Scripts/python.exe`（本机开发） |
| `mcp.args`               | server 脚本的路径，相对项目根                                                                        |
| `mcp.expose_to_llm`      | `false` 时工具对 LLM 隐身，只有你自己的代码能调（如 revive）                                         |
| `trigger.interval`       | 轮询间隔，秒                                                                                         |
| `on_user_reply.function` | 模块级函数，签名 `(bot, user_id, text)` 或 `(user_id, text)` 都行，系统自动适配                      |

`mcp` 字段还能带 `capability` 和 `warmup`（可选）：

```json
"mcp": {
  "command": "runtime/python.exe",
  "args": ["plugins/myplugin/server.py"],
  "capability": "memory",
  "warmup": "breath"
}
```

- `capability`：声明这个插件提供哪类能力（`memory`/`archive`/`event` 或自定义）。
  有了它，机器人主代码可以用能力名调用，不写死你的 namespace。
- `warmup`：启动时预热哪个工具（通常选一个无副作用的，用来建立常驻连接）。

## MCP 服务器（server.py）

用官方 `mcp.server.fastmcp`，stdio 传输。这是完整最小例子：

```python
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("myplugin")   # 名字随意，工具名前缀用 manifest 的 name


@mcp.tool()
def my_tool(keyword: str, limit: int = 10) -> dict:
    """工具描述写清楚干嘛的，LLM 靠这个判断什么时候调用你。"""
    # ... 你的逻辑 ...
    return {"ok": True, "items": [...]}


# 选配：声明这个插件给某用户存了哪些数据（供 /清空 用）
@mcp.tool()
def storage_info(user_id: str) -> dict:
    return {
        "user_data": [
            {"kind": "file", "path": f"data/myplugin/{user_id}.json"},
        ]
    }


if __name__ == "__main__":
    mcp.run(transport="stdio")
```

要点：

- **工具描述用中文写好**。LLM 看描述决定调不调，写清楚输入参数和用途
- **纯函数 + JSON 返回**。参数和返回值都要能 JSON 序列化。
- **数据放 `data/<插件名>/`**，
  `Path(__file__).resolve().parent.parent.parent / "data"` 定位到项目根。
- 如果数据要跨调用共享状态，用模块级变量或文件。每次工具调用是独立进程内的调用，
  stdio 模式下服务器常驻，全局变量是活的。
- `storage_info` 不是必须的，但写了机器人才能在用户要求"清空我的数据"时删掉你的文件。

### MCP 是被动态 不能主动发起与bot的通讯

```
bot 端 trigger 线程定时调 server 的工具
  → server 算完返回"该不该发"
  → trigger 决定要不要发、怎么发
```

revive 就是这个模式：`trigger.py` 每 60 秒调 `love_tick`，返回
`should_send=true` 就让 LLM 写一句问候发出去。

## 调度器（trigger.py）

```python
import threading
from botapp.console import console

_NAMESPACE = "myplugin"


class MyTrigger:
    def __init__(self, bot, interval: float = 60.0) -> None:
        self._bot = bot
        self._interval = interval
        self._stop = threading.Event()
        self._thread = None

    def start(self) -> None:
        if self._thread is not None and self._thread.is_alive():
            return
        self._stop.clear()
        self._thread = threading.Thread(target=self._run, name="myplugin-trigger", daemon=True)
        self._thread.start()
        console.config(f"插件 myplugin 调度器已启动")

    def stop(self) -> None:
        self._stop.set()
        if self._thread is not None:
            self._thread.join(timeout=5)

    def _run(self) -> None:
        while not self._stop.is_set():
            try:
                self._check()
            except Exception as e:
                console.warn(f"myplugin 轮询出错: {e}")
            self._stop.wait(self._interval)

    def _check(self) -> None:
        # 调自己插件的 MCP 工具
        raw = self._bot.tools.call_tool(f"{_NAMESPACE}-my_tool", {"keyword": "x"})
        console.mcp(f"myplugin 返回: {raw[:200]}")


def on_user_reply(bot, user_id: str, text: str) -> None:
    # 用户发消息时被调用，做记录/学习
    pass
```

## 生命周期

- `manifest.json` 扫描：`WeChatBot.__init__` 里 `plugins.load_all()`
- `trigger` 实例化：`instantiate_triggers()`，实例挂到 `bot.<插件名>`，启动时 `plugins.start()` 统一 start，退出时 `plugins.stop()` 统一 stop
- `on_user_reply` 注册：`instantiate_reply_hooks()`，挂到 `bot._user_reply_hooks`，每条用户消息广播

所以你的 trigger 类**必须**有 `start()` / `stop()`，on_user_reply 函数**不能**抛异常（异常会被主流程吞掉打日志）。

## 调试

- 先单独跑 server 看它能不能启动：
  `runtime/python.exe plugins/myplugin/server.py`
  （会以 stdio 方式挂着，能启动说明没语法/导入错误）
- 直接用 `testtool/test_bot.py` 或写个假平台脚本，构造 bot 后调用
  `bot.tools.call_tool("myplugin-xxx", {...})` 看返回
- 日志统一进 `logs/bot.log`，主进程用 `console.info/warn/mcp/config` 打印

## 步骤

1. `plugins/<名字>/manifest.json`（先只写 name + description）
2. 写 `server.py`，注册几个工具
3. `mcp.expose_to_llm` 设为 `true`，启动 bot，看工具有没有出现在 LLM 工具列表
4. 需要主动做事 → 加 `trigger`，写 `trigger.py`
5. 需要监听用户消息 → 加 `on_user_reply`
6. 数据目录用 `data/<名字>/`，别忘 `storage_info`
