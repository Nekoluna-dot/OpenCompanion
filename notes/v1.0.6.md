# v1.0.6 修复记录

> 本文件记录 v1.0.6 版本修复的功能与缺陷，按时间倒序排列。

---

## 配置页 model 字段新增「自动获取」模型列表 + 下拉选择

- **需求**：在「机器人配置（config.ini）」与「OmbreBrain 配置（config.yaml）」页，
  填写 API 地址后点击 model 字段旁的「自动获取」，由后端拉取该地址下的可用模型列表，
  再通过下拉框选择，避免手动拼写模型名出错。
- **现状**：配置页所有非 bool/combo 字段都只渲染一个纯文本输入框；后端没有查询模型的接口。
- **改动**：
  - **新增 `botapp/webconsole/model_list.py`**：`fetch_models(base_url, api_key)` 请求
    OpenAI 兼容的 `{base_url}/models`，解析出模型 id 列表。
    - 候选地址推导：`base_url` 以 `/chat/completions`、`/responses`、`/completions`、
      `/embeddings`、`/models` 等**完整端点**结尾时，回退到同源根路径尝试
      `/v1/models` 与 `/models`；以 `/v1` 结尾只试 `/v1/models`；否则依次试
      `{base}/models` 与 `{base}/v1/models`。
    - 未写协议头时自动补全（本机/`.local` 用 `http`，其余用 `https`）。
    - 网络请求超时 15s；响应统一 `errors="replace"` 解码；失败返回
      `{"ok": False, "error": ...}`（不抛异常）。
  - **`botapp/webconsole/server.py`**：新增接口 **`GET/POST /api/llm/models`**（需鉴权），
    入参 `base_url` + `api_key`，返回 `{"ok": true, "models": [...], "endpoint": url}`。
    同时 `from botapp.webconsole import ... model_list ...`。
  - **`botapp/webconsole/webui/src/pages/Config.vue`**：`model` 字段改渲染为
    「输入框 + 自动获取按钮 + 下拉框」；`fetchModels()` 调 `/api/llm/models`，
    下拉选项保留当前值（防止选中值被清空）。两张配置卡片（ini/yaml）均支持。
  - **`botapp/webconsole/webui/src/assets/theme.css`**：新增 `.model-row` 样式。
- **接口契约**：
  ```
  POST /api/llm/models   Authorization: Bearer <token>
  {"base_url": "https://api.deepseek.com/responses", "api_key": "sk-..."}
  -> {"ok": true,  "models": ["deepseek-chat", ...], "endpoint": "https://api.deepseek.com/v1/models"}
  -> {"ok": false, "error": "..."}          # 拉取失败时
  ```
- **验证**：
  - `npm run build` 通过（47 模块，产出 `static/assets/Config-*.js`）。
  - 后端单测（假 OpenAI 服务）：候选地址推导 6/6、响应解析、直连/端点回退/失败/空地址
    全部通过；真实 `WebConsoleServer` 路由：未鉴权 401、POST/GET 均返回模型列表、
    失败地址返回 `ok=false` 不报错。
  - 无头 Edge 端到端：打开配置页 → 填入 base_url/api_key → 点击「自动获取」→
    展开下拉，选项 = 当前值 + 后端返回的模型列表（实测出现假服务返回的
    `aaa-test-model`、`bbb-test-model`）。
- **关联文档**：`botapp/webconsole/webui/README.md`
