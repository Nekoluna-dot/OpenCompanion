# v1.0.11 修复记录

> 本文件记录 v1.0.11 版本修复的功能与缺陷，按时间倒序排列。

---

## 前端改为 CI / Docker 构建，不再提交构建产物

- **现象**：网页控制台是 Vue 3 + Vite 工程，但构建产物 `botapp/webconsole/static/`
  一直被提交进仓库；CI（`.github/workflows/docker-image.yml`）与 `Dockerfile`
  都**不编译前端**，只是把仓库里现成的静态文件打进镜像。于是：
  - 改了 `botapp/webconsole/webui/src/` 却忘了本地 `npm run build`，
    推上去的镜像仍是旧界面，且**没有任何报错**，很难发现。
  - 仓库里同时存在前端源码和一堆带 hash 的构建产物，容易混淆、易产生冲突。
- **根因**：前端构建没纳入 CI/镜像构建链路，"构建产物入库"这种脆弱做法替代了
  "构建时现编译"。
- **修复**：
  - **`Dockerfile` 改为多阶段构建**：新增 `node:22-slim` 前端阶段，
    先 `npm ci`（利用层缓存）再 `npm run build`（产物输出到 `/static`）；
    Python 运行阶段用 `COPY --from=webui /static ./botapp/webconsole/static`
    把**现编译**的产物覆盖进去。镜像内界面永远与 `webui/src/` 一致。
  - **`.gitignore`**：新增忽略 `botapp/webconsole/static/`
    （与已有的 `node_modules/` 一起，前端依赖与产物均不入库）。
  - **`.dockerignore`**：新增忽略 `botapp/webconsole/webui/node_modules` 与
    `botapp/webconsole/static`，避免本机副本污染构建上下文、覆盖容器内新装的依赖。
  - **`botapp/webconsole/server.py`**：`_send_static` 在 `static/index.html`
    不存在时（源码运行、未构建）返回一个可读提示页（`_send_build_hint`），
    告知如何 `npm install && npm run build`，而不是干巴巴的 404。
  - **文档**：`README.md`、`docs/Docker部署指南.md`、
    `botapp/webconsole/webui/README.md` 补充"构建产物不入库 / Docker 自动编译 /
    源码运行需先构建"的说明。
- **验证**：
  - 本地 `cd botapp/webconsole/webui && npm ci && npm run build` 成功，
    产物写入 `botapp/webconsole/static/`（容器内即 `/static`，与
    `COPY --from=webui /static` 路径一致）。
  - `git add --dry-run` 确认 `botapp/webconsole/static/` 与 `node_modules/`
    均不再被跟踪。
  - `botapp/webconsole/server.py` 通过 `ast.parse` 语法检查。
- **备份**：改动前 `static/` 已存在于工作区（未入库后可随时由 `npm run build` 重建）。
- **备注**：只改构建链路与文档，前端功能、后端 API 均未改动。
