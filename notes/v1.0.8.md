# v1.0.8 修复记录

> 本文件记录 v1.0.8 版本修复的功能与缺陷，按时间倒序排列。

---

## Responses 流式回复恒为空（日志 `[LLM] 输出=0.00s`、`完成，0 字`）

- **现象**：使用本地 OpenAI 兼容代理（`http://127.0.0.1:8787`，CodeBuddy 代理）
  且 `api_type = responses` 时，机器人**完全不回复**：
  ```
  [Agent] 第 1 轮调用 LLM...
  [LLM] 等待=1.21s 输出=0.00s 合计=1.21s
  [Output] 完成，0 字
  ```
  而调试视图里流式内容其实正常显示（`response.output_text.delta` 有文字），
  说明**请求成功、有内容，但机器人侧解析到的 `content` 为空**。
- **根因**：`botapp/llm.py` 的 `_stream_responses()` **只用 SSE 的 `event:` 行**
  判断事件类型（`cur_event`）：
  ```python
  if line.startswith("event:"):
      cur_event = line[...].strip()
  ...
  if cur_event == "response.output_text.delta": ...
  ```
  OpenAI 官方与 DeepSeek 都会发 `event:` 行，所以一直没问题；但**很多兼容代理
  不发 `event:` 行**，只把事件类型写在 data JSON 的 `"type"` 字段里，例如：
  ```
  data: {"type": "response.output_text.delta", "delta": "凌晨"}
  ```
  此时 `cur_event` 恒为空串，`response.output_text.delta` / `output_item.added` /
  `function_call_arguments.delta` 等**所有分支都不命中** → `reply_parts` 永远为空
  → 回复为空、工具调用也解析不到（`_run_agent_inner` 拿到空文本直接结束，
  不报错、不发消息）。调试视图能显示是因为它走的是 `chunk["type"]`，与
  解析逻辑无关，所以"看起来有、发出去没有"。
- **修复**（`botapp/llm.py`，`_stream_responses`）：
  - 事件名优先取 `event:` 行，**缺失时回退用 data JSON 的 `"type"`**；
    再把最终事件名回填到 `data["type"]` 供 rawview 分发。
  - 补 `response.output_text.done` / `response.reasoning_text.done` /
    `response.function_call_arguments.done` 的兜底（只给整段文本、
    不发 delta 的实现也能取到内容；已收 delta 则不重复）。
  - 新增 `type == "error"` / `"response.error"` 事件处理：记为错误并终止，
    不再静默当空回复（代理上游报错时能打印出原因）。
  - 新增"未解析到任何输出"诊断警告：打印收到的事件数与首个事件类型，
    便于下次快速定位同类兼容问题。
- **验证**：
  - 回归单测（`_stream_responses`）：
    A 标准 Responses（带 `event:` 行）→ `你好世界`（无回归）；
    B 代理变体（无 `event:` 行，类型只在 `type`）→ `凌晨三点`（修复项）；
    C 代理变体 + `function_call` → 正确解析出 `tool_calls`；
    E `chat/completions` 路径 → `哈喽`（无回归）。
  - 真实本地 `127.0.0.1:8787` 代理：修复前 `content=''`，修复后
    `content='在的'`（`finish_reason=completed`）。
- **备注**：改动只涉及 Responses 分支；`chat/completions` 分支本就按
  `delta.content` 解析，不受影响。**需重启机器人进程**（`llm.py` 在启动时导入）。
- **关联文档**：`docs/编码与乱码修复说明.md`（其中已说明 `llm.py` 的按行解码安全，
  本次问题与字节编码无关，是**事件类型判定**问题）。
